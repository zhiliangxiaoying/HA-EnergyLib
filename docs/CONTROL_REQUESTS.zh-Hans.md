# 基础参数设置请求

版本：0.8.36.dev1；日期：2026-10-23。

用户要求正常设置不再先读取其他参数。修改仅限EnergyLIB集成的控制路径，不修改HA原生设备页、能源页或前端组件。

## 正常路径

| 参数 | 修改前 | 0.8.34 |
|---|---:|---:|
| EMS模式 | 3次 | 写入＋回读，2次 |
| 单电池备电/放电截止SOC | 3次 | 写入＋回读，2次 |
| 双电池备电/放电截止SOC | 6次 | 每路写入＋回读，共4次 |
| 出口功率、电网充电、出口限制开关 | 2次 | 仍为写入＋回读，2次 |

以上要求已完成初始化、控制状态已加载且连接健康。正常设置不额外读取SN、版本、另一项SOC或远控使能位。写后逐个比较原始寄存器与目标，成功后立即更新HA实体；不会等待整轮遥测刷新。

双电池是否联动取决于设备上报的能力，不取决于电池2诊断实体是否在界面启用。没有将两个寄存器合并成未经验证的批量写入，也没有取消第二路设置或确认。

## 仍保留的检查与恢复

- 控制总权限、参数类型、数值范围和设备已知额定功率限制继续本地校验，不增加通信。
- 本插件正在执行远控任务，或控制缓存显示远控开启时，EMS模式切换立即拒绝，不追加设备读取。只有控制缓存为空（刚启动或通信恢复后）时补读一次0xC646，避免覆盖App刚发起的远控会话。
- “放电截止SOC ≤ 备电SOC”（电池2分别比较）用控制缓存判断：冲突时写入前拒绝，不读取、不写入；缓存里没有对应值时交给写后回读。缓存由每次写后回读和30秒控制轮询更新（0.8.36）。设备自身是否约束仍待厂家确认。
- 连接重建仍核对业务身份、能力；通信失败后的受限重试仍检查当前约束，不把重试中的读取计为正常2次路径。
- 明确拒绝不盲目重发；部分成功、回读不符或取消后不乐观报告成功。首次缺少控制快照及失败恢复仍可追加读取。
- 手动强制充放电、停止和TOU整表保存是多步操作，保留原有执行流程，不按单参数的2次请求承诺。

## 验证范围

回环TCP测试记录每个实际请求：单/双电池场景下，备电SOC、放电截止SOC、EMS模式、出口功率和两个开关都先发FC16，再仅对目标发FC03。同时覆盖设备拒绝、第二路部分成功、重连身份核对、通信重试、写后取消、控制优先级及严格回读。

物理设备本轮仅做只读检查，不自动修改参数。请求减少不等于已证明现场端到端耗时；需要用户下一次正常操作产生的`last_control_timing`和`last_command_timing`区分排队、通信与界面反馈。
