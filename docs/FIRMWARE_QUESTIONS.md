# 固件确认与开放门槛

## 2026-10-22 FC02 只读观察与客户端适配

- 实体采集棒广播型号 WF_ETH、固件 400.3.3，云端逆变器型号 D-TL。仅为本次对象的观察，未确认所有固件行为。
- Unit 1：FC02 从 0x1000 读 1/2/3/4/10 位、从 0x1048 读 201/202 位、从 0x105A 读 1/2/3 位，都有数据 PDU；从 0x1001 读 1/2/3/4 位、0x1049 读 1/2 位均返回 82 03。证据支持起始地址对齐限制，不能归因于数量必须偶数。
- 0.8.16.dev1 在盛弘 profile 中对齐 FC02 请求起点、丢弃前导补读位；运行状态仍按原 0x1001～0x1003 解码。泛用 Modbus 客户端不新增奇偶限制。大块请求按偶数边界拆分，保持每帧不超过现有 202 位上限。
- 回复 MBAP Length 仍出现字节顺序反转，标准客户端继续拒绝。对齐适配不等于已完成正常接入；需厂家修复 Length 后，核对运行位定义、云端状态、告警位与 Unit 2 来源。上述数据 PDU 不作为有效 HA 测量值发布。
- 固件端仍需确认对齐约束的适用范围及错误码原因。Modbus 标准 FC02 没有要求偶数地址或偶数数量。控制未进行实体设备写入测试。

状态：截至 2026-10-19，还没有厂家答复，也没有做过物理设备验证。每条答复都要补充适用型号、固件、证据、确认人和日期；表里没填的不等于已确认。

从 0.5.0.dev6 起，只保留**一个盛弘 V001B031 profile**，真机和软件模拟器（`tools/sinexcel_simulator.py`）走同一套代码。
控制按协议寄存器实现，参考思格的做法：默认关闭，需要在集成选项中打开“允许控制”，并逐个启用控制实体；只有设备能读到全部控制寄存器时才会创建控制实体。
下表“当前假设”是协议没写清楚、代码中暂时采用的做法。未单独注明厂家确认或实机只读观察的项目仍待验证；模拟器按同样假设实现，通过不代表实机验证。

## 2026-10-20 发现协议联调补充

- 设备端确认采用六个必填 TXT 字段及可选 unit_id，明确该地址是否可配置、如何对应真实业务请求。
- api_ver=1 表示单机标准 Modbus TCP 本地业务接口，不替代逆变器点表版本；确认实际 MBAP/Unit ID 透传能力。
- 采集棒 SN 与逆变器 SN 可以不同；尚无采集棒 SN 的业务读回接口，插件只将其保存为广播信息。
