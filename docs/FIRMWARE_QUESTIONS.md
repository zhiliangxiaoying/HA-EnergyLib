# 固件确认与开放门槛

状态：截至 2026-10-19，还没有厂家答复，也没有做过物理设备验证。每条答复都要补充适用型号、固件、证据、确认人和日期；表里没填的不等于已确认。

从 0.5.0.dev6 起，只保留**一个盛弘 V001B031 profile**，真机和软件模拟器（`tools/sinexcel_simulator.py`）走同一套代码。
控制按协议寄存器实现，参考思格的做法：默认关闭，需要在集成选项中打开“允许控制”，并逐个启用控制实体；只有设备能读到全部控制寄存器时才会创建控制实体。
下表“当前假设”是协议没写清楚、代码中暂时采用的做法，模拟器也按同样的假设实现，**都没有经过实机验证**。

| 编号 | 需要厂家确认的事实 | 当前假设 / 实现 |
|---|---|---|
| Q1 | TCP 是否透传 Unit 1/2，是否支持 FC02/03/04/16，最大连接数 | 客户端都支持；状态和告警从 Unit 1、2 读取，写入只发 Unit 1 |
| Q2 | 电池功率、电网功率、电池电流的正负方向 | **已确认（2026-10-19，用户转述盛弘）**：0x1272 电池功率正 = 充电，0x1276 电网功率正 = 馈电（卖电）。插件读到后取反为统一约定（电网正 = 买电，电池正 = 放电），模拟器按盛弘方向输出原始值。**待补充**：0x1210/0x121A 单路电池功率、0x120E 电池电流是否同向（暂按同向处理）；0xC648 写入是否确为“负充正放”（与读数方向相反）；电表 0xA112~0xA124、电网分相 0x102E~0x1032 的方向 |
| Q3 | 心跳的写法、保活周期、超时后的逃生与恢复 | 进入远程控制时写 0xC06A=60 s、0xC06C=1（自发自用）；每 10 s 向 **0xC068 写 1.0（Alive）**；超时后设备自行回退 |
| Q4 | 手动控制、TOU、App、工作模式、开停机之间的优先级 | 远程控制和 TOU 互斥，远程控制期间不允许修改工作模式 |
| Q5 | TOU 总开关地址、暂停机制、写入后的激活方式 | 不写有冲突的 0xC0B0；写时段前先把 0x300C 设为 0（自发自用），写完回读一致后，再恢复原模式或切到 TOU |
| Q6 | 参数存 RAM 还是 EEPROM，写入寿命、限频和重复写要求 | 每次写入后回读，不自动重试；没有做限频（真机前需确认） |
| Q7 | 数量字段的单位、单帧块长度、读到空洞的行为、能否跨 AC/DC 块读 | 保守按单个 float（2 个寄存器）读取，不跨未知空洞 |
| Q8 | 实现代码和协议的分发权限、许可证、品牌使用权 | **代码已决定开源（2026-10-20，所有者确认）**：Apache-2.0，版权人 zhiliangxiaoying。协议原件不随代码分发；品牌图片不在许可证范围内 |
| Q9 | SOC 之间的关系、双电池参数是否需要一致、额定功率与限幅 | 最小 SOC ≤ 备电 SOC（只在写 SOC 时校验）；额定功率取 **0x2008 ÷ 100**，并受协议的 50 kW 上限约束 |
| Q10 | TOU 能否跨零点、能否设 24:00、星期跨周、日期的时区与最大值 | 不支持跨零点（拒绝）、拒绝 24:00；生效日期 0xC0B6/0xC0B8 按 U32 时间戳读取（本地日历日期按 UTC 换算），保存/清空保留设备当前窗口；模拟器新表默认当天至 2099-12-31 |
| Q11 | 各状态位、告警位的含义、组合方式和保留位 | 运行状态取 0x1001 起的 3 个位，**低位在前**组成 0~3（待机 / 就绪 / 离网 / 并网）；告警只给出来源和地址代码 |
| Q12 | 各型号、固件的机器类型、MPPT 路数、BMS、电表、端口用途 | 只按实际读到的值裁剪实体，不根据 mDNS 名称推断 |
